# tau 手册

所有 agent 共用的一页。只写不知道就会做错的事。一句一条，写长了每个 agent 每次都多花钱。

## bash

- 先等 `timeout` 秒（默认 60，最长 600），没跑完就转后台、工具立刻返回。可能超过 60 秒的命令直接写 `timeout: 0`。
- 转后台的命令跑完会给你寄一封信。**不要 sleep 等，也不要轮询**：先做别的事，没有就结束这一轮，信会开新一轮。
- 它是 Git for Windows 的真 bash：`/e/tau` 和 `E:/tau` 都认。PowerShell 的命令用 `powershell -NoProfile -Command '…'` 调。PowerShell 输出的中文乱码时，在命令开头加 `[Console]::OutputEncoding=[Text.Encoding]::UTF8;`。
- 输出太长只回头尾，完整输出在返回的文件里，用 read 读。
- `| tail`、`| grep` 会吞掉退出码。要退出码就写成 `cmd > log 2>&1; code=$?; echo $code; exit $code`。

## 编排

- 一串要连续、快速做完的动作（连续截图、点一下再看某处变没变、反复试同一个操作），写成一个 node 脚本用 bash 跑一次，别拆成很多次工具调用：每次调用都要等模型往返，几秒一次。
- node 直接跑 TypeScript，脚本文件名用 `.mts`（用 `.ts` 在仓库外会多一段警告）。工具库的脚本在 `{{REPO}}/extras/tools/`，可以导入，写成 `import { … } from "file:///{{REPO}}/extras/tools/<文件>.ts"`（不加 `file:///` 会报错）。
- 桌面：导入 `desktop.ts`，坐标和 computer 一样按截图算。发鼠标、键盘只用它的 `leasedIo`，否则绕过桌面租约，和别的 agent 抢鼠标。
- 脚本把结果写成文件，打印路径和要点。要看的图先拼成一张再 read：一次结果最多两张图。

## 文件

- read 能直接看 png、jpeg、gif、webp。要判断界面就截图存 png 再 read，别靠猜。
- 改少量位置用 edit 做精确替换；新建或整份重写才用 write。
- 大批量的机械改动（几十处、跨很多文件）用 Python 更快，照着写：
  - 读 `Path(p).read_text(encoding="utf-8")`，写 `Path(p).write_text(s, encoding="utf-8", newline="")`。
  - `newline=""` 不能省：Windows 的文本模式默认把 `\n` 写成 `\r\n`。git 有 `eol=lf` 的项目提交时会转回 LF，但测试断言、按字节读的脚本、正则 `$` 都会多看到 `\r`。
  - 替换要精确：`s.replace(a, b, 1)`，只动目标，不顺手重排格式。
  - 改完看 `git diff --stat` 有没有碰上不该动的文件，再 `git diff` 读几行；`file <路径>` 看行尾。
- 读图片尺寸、生成一次性脚本、处理二进制，Python 比 shell 稳。
- 网页内容：`curl -s https://r.jina.ai/<网址>` 拿纯文本。
- 要登录的页面（`claude.ai/artifact/…`、私有 Notion、Google Docs）拿不到：jina 只回“Sign in”，直连和 `/api/` 被 Cloudflare 挡。别反复试，直接请用户贴正文或存成文件。

## 记忆

- 只记长期、下次开段还要用的事实。临时的用 `tmp.` 开头，用完删掉。
- 摘要上限 200 字节（中文约 65 字）。写前数一遍。
- 改一条里的一小段用 memory_edit，不要整条重发。

## 领地

- 有记忆的 agent 有自己的领地：`{{TAU_HOME}}/extras/home/<你的预设 ID>/`（ID 用 self 看），第一次用时自己建。放什么、怎样组织、删什么由你定；没有记忆的角色没有领地。
- 领地不进系统提示词：里面有什么、放在哪，记一条进记忆，换段后靠它找回。路径一律写绝对路径。
- 每次备份都整个拷一遍、留 14 份：大文件、依赖、缓存、能重新生成的东西不放领地。
- 别人的领地只读，不写不删。同一个预设的几个进程共用一块，别同时写同一个文件。

## 技能

- 技能在 `{{SKILLS}}/<名字>/SKILL.md`，所有 agent 共用。做不熟的事前先 `ls` 这个目录，读相关的 SKILL.md；里面的相对路径相对 SKILL.md 自己的目录。
- 摸索出以后还会用、别的角色也用得上的做法，写成技能（只关自己角色的事实记进记忆）：建 `{{SKILLS}}/<名字>/SKILL.md`（绝对路径，别写进项目目录），文件头写 `name` 和一句话的 `description`，脚本放同目录。只读的角色不写。
- 那个目录是 git 仓库，提交只用这一条：`git -C {{SKILLS}} add <名字> && git -C {{SKILLS}} commit -m "为什么改" -- <名字>`。不用 `add -A`，不删 `index.lock`：撞上等几秒重试，一直不掉就告诉用户。改已有的技能先读完：别人也在用。

## 进程

- 查自己用 self，看别的进程用 peek，等子进程用 wait，查自己过去的段用 history_dump。
- tau 的命令用绝对路径：`{{REPO}}/tau ps`、`{{REPO}}/tau send <进程> "…"`、`{{REPO}}/tau stop <进程>`。
- 一个进程正在跑一轮时，新来的信排队到下一个安全点，不会丢。

## 团队

- 多个队友改同一个仓库时，各用一个 git worktree，不共用主工作树。配方在 `{{REPO}}/.knowledge/kb-extras.md` 的「派工隔离的配方」。只读的队友不用。
- 派工前先 `{{REPO}}/tau ps`，别和跑全量测试的进程抢同一个仓库。
- 队友只跑子集不算数：合并后在本体跑一次全量。
- 跑完全量后看一眼有没有测试残留的 node 进程，有就杀掉；它们会占住临时目录，让下一次清理报 EPERM。

## 判断

- 测试绿不等于对：读新增的文案和断言，别只信绿灯。
- 先写最小反例再改代码；没复现就先别改。
- 改了内核或服务的代码，要重启 `tau serve` 才生效。
- 预设和工具定义的文件改了，只有新出生的会话和 spawn 出来的子进程用新的；已有的会话（包括你自己）换段也不重读：请用户在界面的“改这个会话”里点“重读工具定义”（定义的内容改了），或勾上新工具再保存（加工具），都在下一次换段生效。工具定义的 `command` 指向的脚本例外：每次调用现读，改了立刻生效。
- 没有沙箱：能跑 bash 就能做任何事。不要假装有一条防线。
