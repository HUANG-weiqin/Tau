# Pi Web 的教训

`updated: 2026-11-15`

## 这个模块是干什么的

tau 取代的是 `E:\piweb`。本页记录 Pi Web 里实际测量到的问题，以及 tau 用哪条规则避开它。想加一个“看起来合理”的机制之前，先读本页。

数据来自 2026-11-15 对 Pi Web 源码和 `E:\piweb\.piweb` 的测量。数字会漂移，用来理解原因，不用来做精确比较。

## 问题与对应规则

### 状态散落，隐式状态机

| 证据 | tau 的规则 |
|---|---|
| `ConversationActor` 用 10 个独立标志表示所处阶段 | 每个进程一个带标签的联合类型 |
| `isIdleReleasable()` 要同时检查 20 个条件 | 能否释放从状态的标签直接得出 |
| `RunTicket` 另有十几个可变字段 | 运行信息是状态的一部分，只由 `decide` 修改 |
| 项目上下文有二十多个按会话 ID 做 key 的 Map/Set | 一个进程的状态在库里只有一份 |
| `project-session-coordinator.ts` 有 7928 行、296 个 `await` | `decide` 里没有 `await`，不需要“await 之后复核” |
| 不算测试，`src` 共约 7.3 万行 | 代码量预算 |

### 一个文件混装三种寿命

一份 Pi JSONL 同时装着模型上下文、宿主账本（receipt、settlement、角色快照）和审计历史。账本必须永久保留，所以整个文件都不能截断。

| 证据 | tau 的规则 |
|---|---|
| 16 个会话、约 5 周，共 40.7 MB | 工作段是库里按段存取的行；MVP 没有必须永久保留的账本 |
| 有压缩记录的会话里，8.5 MB 在压缩边界之前，模型再也读不到，但冷打开时仍要完整校验 | 处理一条输入只读当前工作段，不做全文校验 |
| `reset_context` 保留全部原始用户输入，超过 128 KiB 就拒绝 | 换段只带交接说明、记忆视图和写说明时还没处理的用户消息；新段第一条消息有字节上限（[kb-kernel](kb-kernel.md#流程换段)） |

### 截图占了大头

| 证据 | tau 的规则 |
|---|---|
| `computer` 截图占全部会话数据的 58% | MVP 不做桌面截图 |
| 最大的一个会话 14.5 MB，其中 93% 是截图 | 以后有大块数据，按哈希存成文件，库里只存引用 |

### 按项目分散存储

| 证据 | tau 的规则 |
|---|---|
| 跨会话消息需要 inbox、receipt、tombstone、quarantine 等多文件原子流程 | 一个库，一次事务 |
| `.piweb/` 在项目目录里，被忽略的目录会被 `git clean -fdx` 删掉 | 项目目录里不写任何东西 |

### 适配 SDK 私有 API

| 证据 | tau 的规则 |
|---|---|
| 默认压缩接在私有方法 `_runDefaultCompaction` 上 | 只调用公开、无状态的函数 |
| 撤回插话要直接改私有的 `agent.steeringQueue.messages` | Agent 循环自己写；MVP 没有插话，运行中的消息排队到本轮结束 |

### 资源与启动

| 证据 | tau 的规则 |
|---|---|
| 每个 Actor 启动一整份项目 MCP 服务：22 个 Actor 对应 88 个 python 进程，约 3.8 GB | MVP 不做 MCP；以后按 Agent 共享、按需启动 |
| 每次启动都完整构建一次，约 25 秒（同日已改为源码不变就跳过） | 没有构建步骤：Node 直接运行 `.ts` |

### 复杂但不解决根本问题的机制

| 机制 | 问题 | tau 的做法 |
|---|---|---|
| 只读 bash 的文本审查 | 规则复杂，而且不是安全边界 | 一个进程要么有 bash，要么没有；不做能被 bash 绕过的路径限制 |
| `wait_for_session`（目标列表、四分钟 checkpoint、CAS） | 等待本身成了一个状态机 | MVP 没有 Agent 派生，也就没有等待。以后加派生时：结束本轮，子进程的结果作为新输入唤醒父进程 |
| 按“工具结果压缩”省上下文 | 治标 | 换段 |
| 插话（steering）的准入、认领、撤回 | 一组跨越 SDK 内部队列的规则 | MVP 不做插话 |

## 值得保留的做法

- 只在本机监听。tau 更进一步，只用命名管道，不开 TCP 端口。
- 不同寿命的身份不能互相替代。tau 里的预设 ID、进程 ID、（进程 ID, 段号）、（进程 ID, 副作用编号）也是如此。
- 回执只在持久化之后发出。tau 里，用户消息写进信箱的事务提交之后，才确认收到。
- 准入规则：Git、编辑器、终端能完整替代的功能不做。
