## 这个模块是干什么的

记录跨模块的决定：决定了什么、为什么、放弃了什么。模块内部的决定写在各模块页里。

每条都标明状态：

- **已确认**：用户明确同意或亲自提出。
- **默认**：我提出的默认值，用户还没确认。改它不需要推翻别的决定。

新增依赖也记在这里，写明理由。

## 决策

### D1 从头重写，不在 Pi Web 上重构

- 状态：已确认。
- 理由：Pi Web 的状态散在二十多个容器里，测试按现有结构写成；不删减功能，状态机只会变得更诚实，不会变小。证据见 [Pi Web 的教训](kb-piweb-lessons.md)。
- 放弃：逐步收拢 Pi Web 的 Actor 阶段标志。

### D2 运行时只有预设和进程

- 状态：已确认。用户提出“全局助手 / 项目多 Agent / 临时 Agent”三种划分，以及“记忆是资源，记忆加 Agent 等于干活的会话”。
- 决定：Agent 不是运行时对象，只是预设的名字。三种 Agent 是同一套代码。
- 放弃：
  - 每个 Agent 一个常驻对象：并行时归属不清。
  - “资源也是进程”（所有东西都是带信箱的单元）：统一接口会掩盖资源之间的差异，而且工作区并不归宿主所有。只有进程有信箱。

### D3 同一个 Agent 的进程可以并行

- 状态：已确认。用户的理由：并行进程只共享记忆，只有写记忆时需要处理冲突。
- 放弃：常驻 Agent 一次只做一件事。

### D4 纯 decide、单信箱、事务提交

- 状态：已确认。用户的目标是“状态统一管理，其余都是纯函数”。
- 决定：`decide(状态, 输入) → 新状态 + 新消息 + 副作用`；所有输入进同一个信箱；状态和副作用在同一个事务里提交。
- 放弃：
  - 一个全局 store 加异步 reducer：每次跨越 `await` 都要复核状态，这正是 Pi Web 复杂的来源。
  - 照字面理解“全部纯函数”：SDK 流、子进程和崩溃窗口永远不纯。它们被关进执行器，执行器不做决策。

### D5 换段取代压缩

- 状态：已确认。
- 决定：上下文到阈值时，进程写交接说明，然后开新段。新段由“预设 + 记忆视图 + 交接说明”组成。
- 放弃：Pi 原生压缩；Pi Web 的 `reset_context`，它保留全部原始用户输入，超过 128 KiB 就拒绝，所以长会话下会失效。

### D6 MVP 的记忆是带版本号的键值存储

- 状态：已确认。用户以后会自己设计更抽象、解耦的分层记忆。
- 决定：记忆模块对外只暴露窄接口（视图、读、写、删、列出）。写入带版本号，版本对不上就失败并返回最新值。
- 长期方向（不在 MVP 里）：日志加笔记加整理。并行进程只追加日志，只有整理进程写笔记；笔记不自动删除，只降级。
- 放弃（MVP）：分层记忆、整理、遗忘。

### D7 第一版不做沙箱

- 状态：已确认。用户担心沙箱会让项目变复杂。
- 决定：所有命令只走一个“运行命令”副作用，以后加沙箱只换这一处。原则是：不拦，但能发现（git、版本检查），能撤销。
- 已知风险：一个有 bash 的进程如果被说服，可以删除项目外的文件、读取密钥、联网发送数据。这和 Claude Code 默认模式的风险相同。
- 补充：资源权利是“爆炸半径”，不是安全边界。模型单元能被说服（困惑的代理人问题），沙箱也解决不了这一点。

### D8 一个不可丢的用户级 SQLite

- 状态：已确认。
- 决定：进程状态、信箱、待办副作用、所有项目的工作段、记忆、日志，都放在 `~/.tau/tau.db`。WAL 模式，`synchronous=FULL`。迁移用 `PRAGMA user_version`，备份用 `VACUUM INTO`。
- 放弃：
  - “库可以丢，纯文本才是真相”：这个前提是笔记为纯文本文件；记忆改成键值存储后不再成立。
  - 按项目存数据（像 `.piweb/`）：跨会话消息需要多文件原子流程；`git clean -fdx` 会删掉被忽略的目录；全局助手需要扫描所有项目。

### D9 项目目录里不写任何东西

- 状态：已确认（随 D8）。
- 代价：项目改名或移动后，数据不跟着走。

### D10 自省：同一份投影，同一个入口

- 状态：需求已确认（用户希望 Agent 能像用户一样看到并控制 harness，包括上下文剩余、时间等）；方案是默认。
- 决定：`observe(状态, 现在)` 同时供 UI 和 Agent 使用；Agent 的控制工具是用户命令的子集，进同一个信箱。Agent 只能降低自己的权限，不能提升。
- 放弃：给 Agent 单独做一套状态 API。

### D11 模型层只用 pi-ai，循环和工具自己写

- 状态：已确认。
- 已核实（`@earendil-works/pi-ai` 1.0.0）：`createModels()` 返回带 `streamSimple(model, context, options)` 的模型目录；`calculateCost(model, usage)` 可以算花费；`providers/faux` 提供假模型，可以用于测试。
- 理由：Pi Web 最复杂的代码都源于 Agent 循环不归自己，只能适配 SDK 的私有 API。
- 放弃：`@earendil-works/pi-coding-agent`（143 MB，带扩展、codemode、TUI）。5 个工具自己写。

### D12 SQLite 驱动

- 状态：默认。
- 已核实：`node:sqlite` 在 Node 24.14 上仍会打印 `ExperimentalWarning`。
- 决定：默认用 `better-sqlite3`（同步 API，成熟）。执行清单第 2 步之前再核实一次。

### D13 小而硬

- 状态：已确认。用户要求“小而硬，代码精简干净”。
- 规矩写在 AGENTS.md 的“小而硬规矩”里。

### D14 名字叫 tau

- 状态：已确认。
- 含义：τ = 2π，Pi 的下一代；《τ 宣言》主张用 τ 取代 π；在物理里，τ 是衰减的时间常数，对应“遗忘”。

### D15 MVP 范围

- 状态：已确认。用户认为记忆分层、彻底删除、离开电脑时的通知和审批都是 MVP 以外的细节。
- 范围见[设计稿](../docs/design/mvp.md#mvp-不做)。

## 未确认的默认值

这些都不影响开工，写代码时可以随时改：

| 默认值 | 理由 |
|---|---|
| 日志在 MVP 里只追加，不读取 | 数据当时没记下来，以后就拿不回来；以后可以用日志重建记忆 |
| 项目身份是规范化后的路径 | 最简单；移动项目后需要手工重新关联 |
| 代码量预算 3000 行（不算 UI 和测试） | 逼着做取舍；写到一半时校准 |
| 修改 harness 自身代码，按普通项目工作，用户审核后再加载 | 不需要特殊机制 |
| UI 协议：命令用 HTTP POST，投影和流式文本用 SSE | 比 WebSocket 加自定义协议更小，断线自动重连 |
| 没有 wait 工具：等子进程就结束本轮，结果作为新输入唤醒 | Pi Web 的 `wait_for_session` 很复杂 |
| 工具顺序执行，不并行 | 简单、确定 |
