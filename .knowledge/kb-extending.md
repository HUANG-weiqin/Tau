# 扩展

`updated: 2026-11-15`

## 这一页管什么

本页只给扩展的核心原则和大致方向。具体怎么接，按原则读对应的模块页推出来。这里不写方案，也不写到代码。

该不该做，先看 AGENTS.md 的[准入规则](../AGENTS.md#准入规则)和设计稿的 [MVP 不做](../docs/design/mvp.md#mvp-不做)。本页不改变它们。

## 核心原则

1. **沿着运行循环长，不开旁路。** tau 只有一个形状：输入进信箱，纯函数决定，做副作用，结果作为新输入回来（[运行循环](kb-overview.md#运行循环)）。外面的事只在边上变成一条输入，比如 CLI，将来的定时器。决策和状态不出这个循环。
2. **先说清它是哪一种。** 一件进来的事，是新的输入类型。一种要等的事，是新的阶段。一件要做的事，是工具：只碰库的是库内工具，在事务里做；碰外面世界的是库外工具，由执行器做。新工具不加输入类型和阶段，结果走已有的工具结果。说不清是哪一种，就还没想清楚。
3. **状态只在进程记录和工作段里。** 不在它们之外加可变字段。能算出来的不存。这是 AGENTS.md 的[状态规则](../AGENTS.md#必须遵守的规则)，扩展时最容易被绕开。
4. **先保证崩溃后正确。** 服务在任何时刻被杀，新功能都要处在说得清的状态。库外的事被打断，就报“被中断，结果未知”，不自动重做。先写崩溃和竞态的最小反例，再写代码。
5. **可换的部分只换实现。** 记忆有接口。命令只走 `bash` 一处。前端只依赖线协议。换这三样的实现不动内核。别的不预留接口。
6. **不做假边界，不重复外部工具。** 能被 bash 绕过的限制不做。Git、编辑器、终端能完整替代的不做。

## 大致方向

| 想加的 | 方向 | 已有线索 |
|---|---|---|
| 定时器、自我唤醒 | 新的输入类型，到时间由服务投进信箱。不做成一个一直在等的库外副作用：它会让用户消息一直排队，崩溃后也不会重做 | [D14](kb-decisions.md#d14-yagni-审查移出-mvp-的-20-项) |
| Agent 的控制命令 | 新的输入类型，进同一个信箱 | [D9](kb-decisions.md#d9-自省同一份投影) |
| 推送状态行 | 像 D25 的说明，由 `decide` 写进下一条消息。内容从已有状态算出 | [D25](kb-decisions.md#d25-上一轮没有正常结束时下一条消息加说明) |
| Agent 派生、进程之间发消息 | 库内工具往对方信箱投一条输入。派生出的进程的结果作为新输入唤醒原进程，不做“等待”状态机 | [Pi Web 的教训](kb-piweb-lessons.md) |
| 审批 | 新的阶段：等用户批准 | 无 |
| 新工具、MCP | 新工具按原则 2 分库内、库外。MCP 是库外工具，按 Agent 共享、按需启动 | [Pi Web 的教训](kb-piweb-lessons.md) |
| 日志、整理 | 换记忆的实现。整理由一个进程来做，要先有定时器 | [D6](kb-decisions.md#d6-mvp-的记忆是带版本号的键值存储)、[D14](kb-decisions.md#d14-yagni-审查移出-mvp-的-20-项) |
| 挂载 | 不只是换实现，要改预设和记忆接口。先改 D6 | [D6](kb-decisions.md#d6-mvp-的记忆是带版本号的键值存储) |
| 沙箱 | 只换 `bash` 的实现 | [D7](kb-decisions.md#d7-第一版不做沙箱) |
| Web UI | 新的前端，走线协议，读同一份投影。浏览器连不上命名管道，要开端口，先改 D16 和 AGENTS.md | [D9](kb-decisions.md#d9-自省同一份投影)、[D16](kb-decisions.md#d16-服务只在命名管道上监听mvp-用-cli) |
| 花费统计和上限 | 统计在内核外按全部工作段算，不另存。上限只能看当前段；要跨段，累计值就是正当的状态，换段时带过去 | 原则 3 |
| 图片、截图等大块数据 | 按哈希单独存，消息里只存引用。要存成库外文件，先改 AGENTS.md 的存储规则 | [Pi Web 的教训](kb-piweb-lessons.md) |

表里没有的，按上面的原则推。推不出来，或者要破例，先在[决策记录](kb-decisions.md)写清理由。
