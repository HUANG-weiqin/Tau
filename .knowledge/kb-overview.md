# 总览

`updated: 2026-11-15`

## 这个模块是干什么的

tau 是本机常驻的个人 Agent harness，目标是连续运行很多年。

tau 负责：

- 进程的生命周期：启动、并行、插话、中止、换段、结束。
- 信箱和事务：所有输入怎样排队，状态怎样提交。
- 记忆和日志：Agent 的长期知识，以及原始记录。
- 权限和上限：每个进程能用什么资源，最多花多少。
- 投影：用户和 Agent 看到的同一份状态视图。

tau 不负责：

- Git、编辑器、终端能完整做到的事：diff、历史、回滚、文件浏览、交互式 shell。
- 沙箱、多用户、远程访问、多设备同步（MVP 范围外，见[设计稿](../docs/design/mvp.md#mvp-不做)）。

## 架构

### 三种 Agent，一套代码

运行时只有预设和进程。三种 Agent 的区别只在预设里：

| 种类 | 记忆 | 工作目录 | 寿命 | 数量 |
|---|---|---|---|---|
| 全局助手 | 有 | 预设指定 | 永久 | 1 个 |
| 项目 Agent | 有 | 项目目录 | 到你删除预设 | 每个项目多个 |
| 临时 Agent | 无 | 继承父进程 | 一个任务 | 随用随建 |

- 一个 Agent 可以同时有多个进程。这些进程只共享记忆。
- 临时 Agent 由父进程派生，权利只能是父进程权利的子集。

### 运行循环

```text
输入（用户 / 别的进程 / 定时器 / 副作用结果 / 命令）
        ↓
   信箱（SQLite）
        ↓  每个进程一次取一条
   decide(状态, 输入)              纯函数，无 I/O
        ↓  同一个事务提交
   新状态 + 新消息 + 待办副作用
        ↓
   执行器：开始 / 取消 / 上报
        ↓
   副作用结果作为新输入回到信箱

   每次提交之后：observe(状态, 现在) → 推给 UI，也供 Agent 的 self 工具读取
```

### 状态分三层

| 层 | 内容 | 能否持久 | 崩溃后 |
|---|---|---|---|
| 库 | 进程状态、信箱、待办副作用、工作段、记忆、日志 | 能 | 原样恢复 |
| 执行器活状态 | 子进程、模型流、取消开关 | 不能 | 全部作为“被中断，结果未知”送回 |
| 观察者 | UI 连接、流式文本 | 不需要 | 重连后重新拉取投影 |

## 认知模型

从零重建 tau 只需要四样东西：

1. 一个纯函数 `decide`。
2. 一个信箱，加上“状态和副作用一起提交”的事务。
3. 一个只会开始、取消、上报的执行器。
4. 一个纯函数 `observe`。

判断一个新功能，只问三个问题：

1. 它能不能写成“新的输入类型 + 新的副作用类型”？
2. 它需不需要状态之外的可变字段？需要就不对。
3. Git、编辑器或终端能不能完整替代它？能就不做。

## 坑点

- 把 Agent 当成运行时对象：并行和记忆归属会乱。Agent 只是预设的名字。
- 把流式文本写进状态：库会膨胀，提交频率失控。
- 在 `decide` 里读时钟或 `await`：测试和重放会失去确定性。
- 崩溃后猜测外部世界：未知就报告未知，让模型决定下一步。
- 用摘要压缩“修好”长上下文：用换段。
