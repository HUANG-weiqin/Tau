# 界面执行清单

`updated: 2026-11-17` · **当前：第 0 到 8 步做完。开机自启用户不要；手机以后再做。**

按顺序做。每一步结束时，测试全部通过。界面长什么样、数据从哪来，见[界面设计稿](../design/gui.md)。上层的通用规则见 [kb-extras](../../.knowledge/kb-extras.md)。本清单只列任务和验收，不复述设计。

标着“要用户点头”的，做到那里先问用户，同意了再做。

## 每一步都要做的收尾

1. 运行完成门槛：`npm test`、`npm run typecheck`、`git diff --check`。
2. 这一步实现的细节写进 kb-gui 页，不写进设计稿。设计要改，先改设计稿。
3. 勾选本清单，更新顶部的“当前”。
4. 每一步单独提交。

所有测试都用临时目录和测试管道，不碰真的 `~/.tau`，不连 `\\.\pipe\tau`。

## 第 0 步：骨架

- [x] `extras/package.json`：`"type": "module"`，依赖精确锁定。依赖只有 `preact`、`htm` 和设计稿第 8 节的三套字体。从 npm 装，**要用户点头**。
- [x] 目录：`extras/gui/bridge/` 放 HTTP 桥，是 Node 直接运行的 `.ts`；`extras/gui/web/` 放页面，是浏览器直接加载的 `.js`。
- [x] 页面的纯逻辑放进不碰 DOM 的模块：状态合并、增量读、筛选、标题、当前进程。类型用 JSDoc 写，由 tsc 查（`checkJs`）。
- [x] tsconfig 加上 `extras`，不查 `node_modules`。扫描测试 `test/extras-imports.test.ts` 跳过 `node_modules`。
- [x] 界面的测试放在 `test/extras/gui/`，`npm test` 照旧一次跑完。
- [x] 新建 `.knowledge/kb-gui.md`，登记进 INDEX。

**验收**：空骨架下三条门槛都过。扫描测试不扫 `node_modules`，照样能发现违规。

## 第 1 步：HTTP 桥

- [x] `~/.tau` 的路径和端口能用参数指定。测试用临时目录。
- [x] 照 [HTTP 桥要做的检查](../../.knowledge/kb-extras.md#http-桥要做的检查)收请求：GET 送页面，POST 收接口。
- [x] 转发线协议：一个 POST 带一条协议请求。桥连管道（`TAU_PIPE` 有值就用它），回来的每一行原样分块写回。客户端断开，桥就断开管道。连管道时不半关闭（[kb-service 的坑点](../../.knowledge/kb-service.md#坑点)）。
- [x] 读预设：列出 `presets/` 下的预设，解析 front matter。不导入 `src/`，自己写解析。读不懂的预设照样列出，标上读不懂。
- [x] 写预设：打开项目时新建预设，只写预设认识的字段。文件已经存在就拒绝，不覆盖。
- [x] git：只跑固定的几条只读命令（改动、diff、提交、分支），都带 `--no-optional-locks`。工作目录必须是某个预设的 `workdir`，或者记下的项目文件夹。
- [x] 后台命令：列出 `extras/bg/` 下某个进程的 log，读末尾一段。
- [x] 界面自己的数据：读写 `extras/gui/` 下的 JSON 文件，先写临时文件再改名。
- [x] 选文件夹：经 PowerShell 弹出系统的选文件夹对话框。
- [x] 测试：每条检查的反例；转发对着测试服务（模型用 faux），含 `watch` 的分块推送和客户端断开；git 命令都带 `--no-optional-locks`，工作目录不对时拒绝；写预设不覆盖；改名写入中途失败时旧文件完好。

**验收**：测试全过。在测试服务上，浏览器能打开页面；`Host` 不对、方法不对、`Content-Type` 不对时都被拒绝。

## 第 2 步：界面能用

- [x] 进程状态：先 `ps`，再 `watch`（不带 `process`）。被断开就重连，重新拿快照，再用 `history` 补读。
- [x] 消息流：`history` 带 `segment`，按段号和条数增量读（设计稿第 10 节）。流式文本按 `n` 丢掉过时的。
- [x] 消息的显示：用户消息和信头、助手的文字、工具调用条、bash 输出展开、图片（`blob`）、换段带、交接说明折起。
- [x] 项目窄条：钉住的项目、有动静的项目、“全部”、“+”、总管按钮和在跑数。拖动排序留到第 3 步。
- [x] 进程栏：两组、筛选、搜索、临时进程的标题、空闲折叠。常驻团队一行一个预设，写它的当前进程。
- [x] 主区：铭牌、消息流、写信框（`send`）、停止、出错带和 D25 的预告。
- [x] 新进程弹窗、打开项目弹窗（含新建预设）。
- [x] 视觉：设计稿第 8 节的颜色、字体和材质。
- [x] 测试：纯逻辑的单元测试。至少有：增量读跨过换段、`watch` 重连后不丢不重、标题跳过 `spawn` 的信头、分叉的标题、当前进程的规则、筛选的计数。

**验收**：在测试服务上，模型用 Haiku，从界面走完一遍：打开项目、建预设、开进程、寄信、看着流式文字写完、停止、看到出错带。

## 第 3 步：界面补全

- [x] 详情栏：进程三页（概况、改动、后台），项目三页（概况、分支、后台）。
- [x] 分叉：消息上的入口、铭牌的按钮、从出错前分叉。
- [x] 聚焦项目：成员表、最近动态、全部停止（先停子孙，反复做到都空闲）。
- [x] 总管弹窗和“待你看”。
- [x] 全部项目弹窗：搜索、钉住、拖动排序。
- [x] 清理弹窗：先列清楚，再从叶子起逐个 `remove`，被拒的列出来。没人引用的图片用 `sweep`。
- [x] 测试：全部停止的顺序、清理的顺序和被拒、“待你看”的计算。

**验收**：在测试服务上，从界面分叉一个进程、全部停止一个项目、清理一批旧进程，结果和 `ps` 对得上。

## 第 4 步：打磨

- [x] 动效和三档时长（设计稿第 9 节）。系统开了“减少动画”时全部瞬间切换。
- [x] 键盘：设计稿第 9 节的全部按键。
- [x] 进程栏：吸顶的组头、位置尺。
- [x] 手机宽度。

**验收**：内置浏览器 390 宽下没有横向滚动，弹窗铺满屏幕。键盘能走完第 2 步的验收流程。

## 第 5 步：装机

这一步改的是真的 `~/.tau` 和这台电脑。每一项都**要用户点头**。

- [x] 预设：总管、各项目的 Agent、临时进程用的。模型由用户定（DeepSeek V4.1，经 `opencode-go`）。提示词先起草，用户改。
- [x] 第一次在真的 `~/.tau` 上启动服务和桥。
- [ ] 开机自启：任务计划程序在登录时直接运行 node，起服务和桥。用户不要，不做。
- [ ] 手机：Tailscale Serve 指向桥，只用 serve，不用 funnel。可以以后再做。

**验收**：重启电脑以后，浏览器打开页面就能用。

## 第 6 步：第一批工作台功能

只用 API key；不做 OAuth 订阅，不管本地模型。key 继续放在 pi 的 `auth.json`，界面只显示配了没有，这一批不改 key。界面不显示 token 和费用。内核 `src/` 不动。

- [x] 桥：`/api/models`（pi-ai 的目录，加每家的 key 状态，key 的值不出桥）。`extras/package.json` 加 pi-ai，锁 1.0.0。
- [x] 桥：`/api/presets/update`（只换收到的字段，写完 `check`，不行改回旧文件）；新建预设也收 `thinking`、`handoff`、`options`。
- [x] 模型选择器：按供应商分组、搜索、最近用过、key 状态、窗口和能不能收图和思考级别；新建预设、打开项目、改预设共用。
- [x] 思考强度：分段按钮，换模型时取支持的最近一档并提示。
- [x] 改预设：常驻团队行的右键菜单、详情栏概况页；概况页显示进程冻结的模型、思考强度、`options`。
- [x] 换模型：铭牌上的按钮，改预设再带 `preset` 分叉，或者换同项目的另一个预设分叉。
- [x] 设置：默认模型、默认思考强度、供应商和 key 状态（只读）、清理天数；`Ctrl+,`。
- [x] 测试：桥（目录、key 状态不泄漏、改预设和改回去、新建带新字段）；纯逻辑（窗口、最近一档、搜索、排序、最近用过、默认模型、表单变请求、换模型的补丁）。
- [ ] 以后：界面改 key（现在只读）；本地模型；OAuth 订阅。

**验收**：在测试服务上，从界面走完一遍：改预设的模型，看到检查条；故意填一个装不下的换段阈值，看到错误原文、文件改回；给一个出错的进程换模型，聚焦到新进程。

## 第 7 步：第二批工作台功能

内核 `src/` 不动。computer（截屏、点击）暂时不做。出错后的“继续”按钮不做：内核在拿到响应之前会重试，真出错了直接写信就行。

- [x] Markdown：助手的最终文字（消息流和总管弹窗）吐完以后换成排版。marked 加 DOMPurify，原始 HTML 按文字显示，链接只认 http、https、mailto。代码块带“复制”。
- [x] 完成通知：人建的进程跑完一轮、任何进程出错，页面不在前台时弹系统通知；标签页标题带 “(N)”，favicon 加黄点。开关在设置里。
- [x] 工具库 `extras/tools/`：`shell`（输出太长存文件给路径）、`bg_run`（放后台、立刻返回、跑完寄信）、`peek`（看别的进程）、`wait`（同一轮里等子进程）。
- [x] 工具定义页：列已装的定义和工具库，安装、更新、删除（被预设用到时不让删）；预设表能勾选工具定义。
- [x] 记忆页：看、改、加、删带记忆的预设的键，写入带版本号，冲突时不覆盖。
- [x] 项目的 AGENTS.md：建预设、改预设时可勾选，拼在提示词末尾由界面管的一段；文件改过以后，项目概况提示“重新拼”。
- [x] 测试：工具库对着真的服务和 Git Bash；桥的工具路由和 AGENTS.md 的拼、拆、过期；纯逻辑（Markdown、通知、记忆的冲突）。

**验收**：在测试服务上，从界面走完一遍：Markdown 的表格、代码块、坏链接；装一个工具定义并在新预设里勾上；新预设拼上 AGENTS.md，改文件后“重新拼”；记忆页加一条。

## 第 8 步：第三批工作台功能

内核 `src/` 不动。

- [x] 实时看思考和工具调用：watch 带 `messages: true`，追加的消息直接并进消息流，不再每步重读 history；思考和参数边到边显示，一步写完换成折叠块。
- [x] 图片：超过入口条件时在页面里缩放压缩；拖入、选文件；总管弹窗也能贴图；压缩没完不许寄出；模型不收图时提示。
- [x] 详情栏：段尺上的“自动换段”刻线；排队的信；谁在等谁的回信。
- [x] 重启：`cleanenv.ps1` 重建干净环境，`start.ps1`、`restart.ps1` 共用；服务或桥跑着旧代码时横幅提示，按钮重启，有进程在跑先确认；断开时“拉起服务”；`/web/` 不缓存。
- [x] 人建的临时进程用模型自动起标题，模型在设置里选；人改的名字优先。
- [x] 项目页“正在做”等处的第一行去掉 Markdown 标记。

**验收**：在测试服务上，从界面走完一遍：看思考边到边出现；贴一张超大图寄出不被拒；新开临时进程看到自动标题；横幅的重启按钮走到（假的）重启。
