# 界面设计稿：调度台

`updated: 2026-11-17`

状态：设计稿，大部分已实现。样稿在画布 <https://claude.ai/artifact/WohRyk1nnRHQ9sFQeFtyaP> 上（私有）。按[界面执行清单](../plan/gui-checklist.md)做。

图形界面是上层建筑，不改内核。本文写它长什么样、怎么用、每块数据从哪来，以及内核现在给不了的几处。上层的通用规则（放在哪、依赖什么、HTTP 桥的检查）见 [kb-extras](../../.knowledge/kb-extras.md)。

## 1. 定位

- 界面是内核的又一个客户端。它经线协议读写（读预设用 `check`，读进程冻结的预设用 `inspect`），写和删预设文件，在工作目录里跑 git。它不读 `tau.db`，不导入 `src/`。
- 项目目录里不写任何东西。git 一律带 `--no-optional-locks`：普通的 `git status` 会顺手刷新索引，持有 `index.lock`，和 Agent 自己的 git 抢锁。
- 界面自己的数据放在 `~/.tau/extras/gui/`：哪个预设是总管、预设的显示名、每个预设的当前进程、钉住的项目和顺序、项目简称、打开过的文件夹、界面自己建的进程、折叠状态、清理的天数、第一封信的缓存、最近用过的模型、默认模型和默认思考强度。
- 页面用浏览器打开，手机经 Tailscale Serve 打开同一个页面。页面由 HTTP 桥用 GET 送出，接口照旧只收 POST（[HTTP 桥要做的检查](../../.knowledge/kb-extras.md#http-桥要做的检查)）。
- 前端用 Preact 加 htm。浏览器直接加载 ES 模块，没有构建步骤。字体也放在本地，页面不连外网。依赖写在 `extras/` 自己的 `package.json` 里（[D63](../../.knowledge/kb-decisions.md#d63-上层的依赖随便加)）。
- 界面不显示 token 用量和费用。上下文占窗口几成照常显示。
- 三种 Agent 都是预设（[设计稿第 2 节](mvp.md#2-预设)）。界面里的“总管”是全局助手的进程，“常驻团队”是带记忆的项目 Agent，“临时进程”是不带记忆的。

## 2. 布局

从左到右五块：

| 块 | 宽 | 放什么 |
|---|---|---|
| 项目窄条 | 72 | 项目按钮、“全部”、打开项目、总管按钮、全局在跑数 |
| 进程栏 | 约 272 | 聚焦的项目里的进程 |
| 主区 | 余下的 | 聚焦的进程或项目 |
| 详情栏 | 约 356 | 聚焦对象的详情，分页 |
| 选项卡 | 52 | 竖在最右边，和项目窄条对称 |

- 点窄条上的项目，就聚焦这个项目。点进程栏里的进程，就聚焦这个进程。
- 聚焦的时候，主区和详情栏只放聚焦对象的信息。全局的东西收进窄条和弹窗。
- 总管不常驻，点一下才弹出来。
- 手机宽度下，各块从上往下排，弹窗铺满屏幕。

## 3. 项目窄条

- 内核里没有项目。项目就是一个文件夹：界面按每个进程的预设的 `workdir` 把它归到项目下。
- 总管的预设不归进任何项目。它的 `workdir` 不是项目目录（[设计稿第 2 节](mvp.md#2-预设)），界面靠 `~/.tau/extras/gui/` 里记的预设 ID 认出它。
- 从上到下分四段：
  1. 钉住的项目。最多 9 个，编号就是 Alt+1…9。顺序由用户拖动排，也能用 Alt+Shift+↑↓ 挪。
  2. 有动静的项目。没钉住的项目里有进程出错或在跑，就自己露出来：虚线框，不带编号，出错的排前面。安静了就退回“全部”。它和上一段之间隔一条斜纹。
  3. “全部”和“+”。“全部”打开全部项目面板（Alt+0）。“+”打开“打开项目”弹窗。
  4. 底座：设置按钮、总管按钮和全局在跑的进程数。窗口矮了，只有上面三段滚动。
- 角标只有两种：橙色是有进程出错，黄色是有进程在跑。两种都有时显示橙色。
- 按钮上写两到五个字的简称。悬停时浮出一块牌子，写全名、路径和计数。右键可以钉住或拿下。
- 聚焦的项目反成浅色，左边一条黄。

## 4. 进程栏

- 最上面是项目名，点它聚焦项目。下面是三个筛选按钮“全部 / 在跑 / 出错”，按钮上带计数。再下面是搜索框和“新进程”。
- “在跑”是阶段为 `awaitingModel` 或 `awaitingTool` 的进程。“出错”是空闲、上一轮以出错结束的进程。
- 进程分两组：预设的工具里有 `memory` 的是常驻团队，没有的是临时进程。
- 预设只有 ID。显示名（例如“渲染”）是界面自己记的，没记就显示预设 ID。不要往预设文件里加字段：读预设时，不认识的字段会让启动失败。
- 常驻团队的位置不随状态变。每行写编号、显示名、预设 ID、在做什么、三相灯和上下文占窗口几成。三相灯是三个方块，亮的那个是当前阶段。
- 常驻团队一行是一个预设。同一个预设能有好几个进程：又开了一个，或者分叉出来的。行上写的是其中的当前进程：
  - 界面开的进程（新建或分叉），和用户寄过信的进程，成为当前进程。没记过的预设，取最近有动静的进程。
  - 同一预设的其它进程折在这一行下面，写“另有 N 个”。在跑和出错的不折。
  - 点开其它进程，可以把它设为当前进程。
- 团队行带一个角标，写它开的进程里有几个在跑。
- 常驻团队的组头有“+ 预设”，打开“新预设”弹窗（[7.6](#76-新预设)）。
- 右键进程行出一个菜单，能删掉这个进程（[7.7](#77-删除)）。没有任何进程的预设行，右键能删掉这个预设。
- 临时组里，出错的排最前，在跑的其次。这两类永远不折。
- 空闲的临时进程折成一行“空闲的 N 个”。展开以后按今天、7 天内、更早分段。更早的只留一行和清理按钮。
- 临时进程共用一个预设，所以一行的标题用第一封信正文的第一行（[子进程的标题](../../.knowledge/kb-extras.md#pi-web-的功能在-v2-上的做法)）：
  - `spawn` 建的进程，第一条消息是进程的信。标题取这封信的正文，信头不算（信的边界读消息的 `tau`）。
  - `fork` 出来的进程没有自己的第一封信。界面自己分叉的，标题沿用源进程的，写“分叉自 <ID>”；别处分叉的，标题写进程 ID。
- 标题下面写进程 ID 和谁开的。有 `parent` 写父进程。没有 `parent` 的，界面自己建的写“你开的”；其余的（CLI、别的程序、Agent 在 bash 里运行的 `tau start`）写“没有父进程”。
- 搜索框搜预设 ID、显示名、进程 ID 和标题。折起来的进程也搜，命中的直接露出来。没命中的组只剩组头。
- 筛选以后，底下写藏了多少个，一点就回到全部。
- 列表滚动时组头吸在顶上。列表长到要滚时，右边出一条位置尺，标出出错和在跑的进程在哪，框是正看着的那一段。

## 5. 主区

### 5.1 聚焦进程

- 顶上是黄色铭牌：显示名、预设 ID、阶段、在当前阶段待了多久、父进程。右边是上下文占窗口几成的大数字和段尺，以及两排紧凑动作按钮：上排“分叉”“换模型”“换段”，下排“停止”“删除”。
- 消息流按时间排，左边是时间戳：
  - 换段的地方有一条带，写“第 n 段从几点开始”。交接说明默认折起。
  - 中间的消息太多时，折成一行“中间还有 n 条消息”。
  - 进来的信按消息的 `tau` 显示：谁寄的，写信时它在不在等回信（有 `replyTo`）。回信写那一轮的结束原因。这些是写信那一刻的；那一轮结束以后，“它在等回信”就不再成立。
  - 信前面“上一轮没做完”的说明，读 `tau.after`，写成“上一轮被停止”这样的一行。没有 `tau` 的旧消息（D64 以前写进段的）按普通的用户消息显示，整段文字是一封你的信。
  - 工具调用是暗色条：工具名、参数摘要、结果摘要。bash 的输出能展开。
  - 模型正在写的文字匀速流出来，像走纸（2026-11-17 用户在三套实样里选的）：
    - 网络一块一块地到，屏幕上照样匀速出字。平常落后不到半秒，写完时半秒左右追平。
    - 刚出的字在 0.2 秒里由淡到实。末尾是一个不闪的墨块光标，字追平以后淡出。
    - 等模型的状态条在字的下面，像出纸口。字追平以后它收起来，工具条在原地长出来。
    - 写完以后换成 `history` 读到的最终回复。还没出完的字接着出，不重来。
  - 模型在想、在写工具调用参数时，边到边显示（`watch` 带 `messages: true` 才有，见[第 10 节](#10-数据从哪来)）：
    - 思考是消息流末尾的一个暗色小块，标“思考中”和字数。字直接追加，不匀速吐。收起时只留最后 6 行，贴着底；展开能滚，新字来了跟到底，往上滚着读时不拽。
    - 工具调用的参数是一个暗色小块，写“工具调用”和参数字数，下面一行等宽、只留最后一截。服务推来的只是参数的 JSON 片段，没有工具名，所以不写名字。
    - 思考块在最终回答的上面，参数块在下面，都比回答低一档：暗底暗边，小字，不抢重心。
    - 这一步写完，思考块换成原有的折叠块“思考 · n 字”，参数块换成正式的工具条。消息比 `update` 晚到一点时，先留住思考，不先消失再出现。
  - 助手的最终文字按 Markdown 渲染，用户的信、工具输出、思考块不渲染：
    - 吐字期间是纯文字。字追平以后，或者本来就是历史消息，换成渲染后的结果。
    - 支持 GFM：表格、删除线、任务列表。不做语法高亮。
    - 文字里的原始 HTML 不渲染，按文字显示。
    - 链接只认 http、https、mailto，在新标签页打开。图片不加载，显示成链接。
    - 总管弹窗里总管说的话同样渲染，吐字规则一样，配色换成暗面的。
    - 代码块是深底，右上有“复制”。长行在块里横向滚动，不撑破消息流。
  - 进程在跑时，一眼要看得出它还在动。等模型时，消息流末尾是一条状态条：写模型在想、在写还是在写交接说明，以及跑了几秒，底下一道扫描线一直在走。等工具时，正在跑的工具条标签换成信号黄，写“运行中”和跑了几秒，底下也有扫描线。秒数每秒都变，系统要求减少动画时也看得出在动。
- 消息流的一栏跟着主区变宽，最宽 1240px。再宽，一行字太长，不好读。
- 底下是写信框，寄出就是 `send`。它是一条暗色的底座，像调度台的操作台：
  - 消息区是主角，写信框不抢高度。900 高的屏幕上，空着时整条不超过约 130px。
  - 顶上一道斜纹钢边。左块写给谁：拉宽的 LETTER、很重的名字、预设 ID、进程 ID、第几段和上下文、三相灯和在这个阶段待了多久。
  - 右边是墨井，平时露出两行。写长了往上长，最高约台面高度的两成，再多就在框里滚。
  - 墨井底行写寄出以后会怎样，从阶段算。空闲：NOW，立即开始新一轮。在跑：黄色的“NN 封在排队”，下个安全点并进这一轮。旁边是寄出键，框里有字时变黄。
  - 写信时顶边亮一道黄线，墨井四角换成黄色括号，LETTER 变黄。
  - 能贴、拖、选图片：墨井下面一行有“添加图片”和张数。拖进来时墨井出虚线框，写“松手，把图片放进来”。
  - 图片在页面里先处理，处理规则见[5.4](#54-图片)。聚焦进程冻结的模型不收图片时，附图旁写“这个模型不收图片，图会被省略”。
- 铭牌上的段尺画一道刻线，标签“自动换段”，位置是换段阈值占窗口的几成。上下文到阈值的九成以上，尺和刻线变警告色。
- “分叉”用 `fork`（[kb-kernel 的 fork](../../.knowledge/kb-kernel.md#fork)）：
  - 从当前段里某条用户消息之前分。所以分叉的入口只放在当前段的用户消息上。
  - 不指定位置时复制整个当前段，这时源进程必须空闲。铭牌上的“分叉”按钮走这一条，进程在跑时不可用。
- “换模型”是分叉的一种，规则见[7.10](#710-换模型)。
- “停止”用 `stop`。它只停这一轮，后台命令不会跟着停。
- “删除”用 `remove`，进程在跑时不可用（[7.7](#77-删除)）。
- “换段”寄一封换段信：`send` 带 `handoff: true`（[kb-kernel 的换段信](../../.knowledge/kb-kernel.md#换段信)）。信的正文写明这封信没有别的事要做。
  - 内核在下一次调用模型时换段。信原样带进新段，模型在新段里回一句“已换段”。消息流里看得见：它在交接说明下面，“带过来的用户消息”里。
  - 段里已经有助手消息，标记才生效。新进程的第一封信、刚换段的新段开头没有，标记作废，信只是一封普通的信。这两种情形下按钮不可用。
  - 进程在跑时按钮也不可用。运行中到的信排到安全点，这一轮要是出错或被停止，标记就作废。
  - 用处：上下文很大、要隔一阵才回来时，先换段。隔久了，模型那边的缓存过期，下一轮要按整段重新算；换过段，下一轮只带交接说明。
  - 写交接说明要带着旧段调一次模型，所以趁刚停下、缓存还在的时候点。新段里再调一次模型处理这封信，只带交接说明。
  - 上下文到阈值时内核自己会换段。想让它早点换，在预设里写 `handoff`（[设计稿第 2 节](mvp.md#2-预设)）。
  - 总管弹窗里也有“换段”，规则一样。

### 5.2 进程出错

进程空闲、上一轮以出错结束时，主区这样变：

- 铭牌从黄换成警示橙。
- 被中断的工具调用标“被中断，结果未知”，排在它后面的标“未执行”。这两句是内核补的结果原文（[kb-kernel 的常量](../../.knowledge/kb-kernel.md#常量)）。
- 这一轮的结尾是一条暗色带：
  - 结束原因。它取自投影，超过 1024 字节的已截短，换行换成了空格。
  - 两个动作：看改动、从出错前分叉。“从出错前分叉”从这一轮开头那封信之前分。那封信不在当前段时（这一轮中途换过段），只能复制整个当前段，按钮上写明。
- 写信框的墨井顶上预告：下一封信前面会自动加上一轮的说明，只占一行，全文在悬停提示里（[D25](../../.knowledge/kb-decisions.md#d25-上一轮没有正常结束时下一条消息加说明)）。
- 界面不自动重做任何事。重不重做由用户定。

### 5.4 图片

- 入口条件照服务（[kb-service 的图片](../../.knowledge/kb-service.md)）：一封信最多 2 张，每张不超过 1.5 MiB，宽和高不超过 2000 像素，类型 png、jpeg、gif、webp。常量在 `lib/image.js` 里写了一份，测试对着 `src/` 的真常量查。
- 原图合格，原样发。
- 不合格，在页面里用 canvas 处理：
  - 先把长边缩到 2000 以内。png、jpeg、webp 先试原格式。
  - 超了字节上限，转 JPEG，质量 0.9、0.8、0.7、0.55、0.4 往下试。透明背景垫白底。
  - 还超，边长再乘 0.75、0.5、0.35，每一档试两个质量。全不行，提示压不下来，这张不加。
  - gif 和浏览器编不了的格式也转 JPEG。动图只剩第一帧。
- 到 2 张就不能再加，写一行说明。一次选了太多，多的丢掉并说明。
- 总管弹窗的输入框一样能贴、拖、选图片，发出时带 `images`。

### 5.3 聚焦项目

- 铭牌写项目名、路径、git 仓库和分支。右边是常驻团队里在跑的个数和“全部停止”。
- “全部停止”照[停一棵进程树](../../.knowledge/kb-store.md#进程之间的工具)的做法：先停子孙，再停祖先，反复做，直到项目里的进程在 `ps` 里都空闲。被停止的一轮照样寄回信。父进程在项目外（例如总管）时，回信会唤醒它；界面提示这一点，不去停它。
- 成员表：每个常驻进程一行，写阶段、在做什么、上下文。
- 最近动态：进程之间的信、出错、换段，新的在上面。
- 写信框写给成员表里选中的进程，默认是第一个。

## 6. 详情栏

选项卡竖在最右边，上面带小计数：改动的文件数、在跑的后台命令数。

聚焦进程时有三页：

| 页 | 内容 |
|---|---|
| 概况 | 本段消息数、本轮步数、信箱里待处理的条数；当前段的上下文占窗口几成，尺上有“自动换段”的刻线，前面每段在哪里换的；上下文是一块小铭牌：占比大数字、和铭牌一样的十格段尺、尺下面的“自动换段”刻线和位置，近了变警告色，下面一行一段列前面各段；信箱（有排队的信或有等回信的关系时才出现）：排队的信一封一张卡，写谁寄的和第一行（两行截断），只读不能撤回；“等它回信”和“它在等”各一行，没有就不显示；模型、思考强度、换段阈值、`options`、工作目录、工具、带不带记忆；这一栏下面是“改预设”，带记忆的再加“记忆” |
| 改动 | 工作目录里的 git 改动，按目录排成树，点文件弹出它的 diff；最近的提交。这是工作目录的改动，几个进程共用一个工作目录时，页面上明说分不出是谁改的 |
| 后台 | 按[后台命令的配方](../../.knowledge/kb-extras.md#后台命令和完成通知的配方)跑的命令：名字、退出码或“没看到退出码”、log 的末尾 |

改动页的文件树按目录折叠，点目录行收起或展开。文件超过 15 个时，一开始只展开最上一层。

改动页只显示 git 的原样输出：`git status` 列的文件、`git diff` 的文字、`git log` 的提交。diff 由 git 算，界面不自己算，也不浏览、不编辑文件，所以不违反准入规则“Git 负责 diff 和历史”。手机上没有编辑器，要在手机上看改动，这一页省不掉。

聚焦项目时有三页：

| 页 | 内容 |
|---|---|
| 概况 | 在跑、出错、预设的个数；位置和仓库；各预设的模型、思考强度、带不带记忆、工具，每个预设一个“改预设”，带记忆的再加“记忆”。预设拼的 AGENTS.md 比文件旧时，这一行多一个“AGENTS.md 改过了”标记和“重新拼”按钮（只对新进程生效）；文件没了时写“AGENTS.md 没了” |
| 分支 | 各分支领先主分支几个提交、合没合并、增删多少行 |
| 后台 | 这个项目里所有进程的后台命令 |

概况页的信箱和刻线都来自 `inspect`（原样的进程记录和 `limits`，[kb-gui](../../.knowledge/kb-gui.md#详情栏的数据)），界面不显示 token 数，只画比例和刻度。

概况页的模型、思考强度、`options` 来自 `inspect` 读到的快照，不读预设文件。文件之后改了，进程不变。

内核给不了的数据不放进详情栏，见[第 11 节](#11-不显示的)。

## 7. 弹窗

所有弹窗都贴着打开它的按钮，按 Esc 关。例外是 diff 窗：它居中、占满高度，因为它要宽。

### 7.1 总管

- 总管是全局助手的进程。哪个预设是总管、用它的哪个进程，记在 `~/.tau/extras/gui/`。
- 弹窗里是和它的对话，也就是它的当前段。
- 顶上的“待你看”由界面自己算，不靠模型：出错的进程，以及说做完了、分支还没合并的进程。
- 写信时带上当前在看的对象：界面在信的开头加一句“在看 <ID>”。
- Ctrl+K 打开或关上。

### 7.2 新进程

- 第一步选预设：列出工作目录是这个项目的预设。同一个预设能开好几个进程，它们共用这个预设的记忆库。要临时的，就选不带记忆的预设。
- 没有合适的预设，点“新建预设”打开“新预设”弹窗。建好以后回到这里，选中新建的预设。
- 第二步写第一封信。内核建进程要的就是预设和第一封信，等于 `tau start <预设> "<信>"`。
- 建好的进程 ID 记进 `~/.tau/extras/gui/`，进程栏里写“你开的”。带记忆的预设，新开的进程成为它的当前进程。

### 7.3 打开项目

- 选一个文件夹。这个文件夹还没有预设时，当场建一个项目 Agent 的预设：ID、模型、带不带记忆、工具。预设写到 `~/.tau/presets/<ID>.md`，只写预设认识的字段。表里的“模型”是[7.8](#78-模型和思考强度)的选择器。提示词可以现在写，也可以以后用“改预设”补。
- 也可以只记下文件夹，记在 `~/.tau/extras/gui/`，项目先空着。
- 已经有预设的文件夹，在“新预设”弹窗里再加预设。

### 7.4 全部项目

- 列出全部项目，能按名字和路径搜。
- 分两组：钉在窄条上的，能拖动排序；没钉的，按最近的动静排。
- 每一行都能钉住或拿下。

### 7.5 清理旧进程

- 清理的是空闲超过 7 天的临时进程，和常驻团队里不是当前进程的进程。当前进程不清理。天数由界面定，记在 `~/.tau/extras/gui/`。
- 动手之前先列清楚：这次删几个，哪几个删不了、为什么。删不了的情形就是 `remove` 的拒绝条件（[kb-store 的存储事务](../../.knowledge/kb-store.md#存储事务)）：
  - 它开的进程还在：按 `parent` 查，事先列出来。
  - 有进程要给它回信、信箱里有它的输入：界面看不到，不去估。删的时候 `remove` 会拒绝，删完把被拒的和原因列出来。
- 删掉的是进程记录和它的全部段，删了找不回。记忆不动。没人引用的图片另外用 `sweep` 清。
- 用 `remove` 一个一个删，从叶子删起。

### 7.6 新预设

- 给聚焦的项目再加一个预设。工作目录就是项目的文件夹，不能改。
- 和“打开项目”里建预设的是同一张表：预设 ID、模型、思考强度、带不带记忆、工具、换段阈值、提示词、折起的高级。多一栏显示名，可以不填。
- 模型默认取这个项目里已有预设的模型；项目里还没有预设，取[设置](#711-设置)里的默认模型。
- 工具区下面有一个勾选“拼上项目的 AGENTS.md”，旁边小字写文件大小（D58，细节见[kb-gui](../../.knowledge/kb-gui.md#拼-agentsmd)）。
  - 项目里有 `AGENTS.md`：新建时默认勾上。没有：勾选不可用，写“项目里没有 AGENTS.md”。只认这个文件名，不认 CLAUDE.md。
  - 勾上以后，建预设时读一次文件，拼在提示词末尾，前后各一行标记，写明由界面管、别手改。
  - 一行说明：只对新进程生效，在跑的进程冻结着旧的。
- 预设写到 `~/.tau/presets/<ID>.md`。这个 ID 已经有了就拒绝，不覆盖。显示名记在 `~/.tau/extras/gui/`。
- 入口：常驻团队组头的“+ 预设”，新进程弹窗里的“新建预设”。

### 7.7 删除

- 删进程用 `remove`，一次删一个。入口是铭牌上的“删除”和进程行的右键菜单。
- 先弹确认框，贴着按钮。框里写删的是谁（显示名或标题，加进程 ID）、当前段有几条消息、删了找不回。记忆不动。
- 它开的进程连带一起删。`remove` 不删有子进程的进程，所以界面按 `parent` 找出整棵子树（子进程、孙进程……），在确认框里列出来，写一共删几个。按钮上写个数。
- 从叶子删起，最后删它自己。框里写删到第几个。
- 子树里有进程在跑，就不让删，写明哪几个在跑，要先停止。不替用户去停：停下的一轮会给等回信的父进程寄回信，把父进程又唤醒。
- 看不见的两条拒绝条件（有进程在等它回信、信箱里有它的输入）照常去删。一个被拒绝，它的祖先也删不掉，就跳过它们，别的分支照删。删完在框里列出没删掉的和原因。
- 删之前先缓存子树里每个进程的标题：从它们分叉出来的进程沿用这些标题。
- 删的是常驻团队的当前进程时，界面忘掉这条记录，按第 4 节的规则重新挑当前进程。删的是正在看的进程时，主区回到它的项目。
- 删进程不顺手 `sweep`。没人引用的图片在“清理旧进程”里清。
- 删预设只对没有任何进程的预设开放，入口是团队行的右键菜单。删的是 `~/.tau/presets/<ID>.md`，记忆库不动：以后用同一个 ID 建预设，记忆还在。总管的预设不在这里删。

### 7.8 模型和思考强度

新建预设、打开项目、改预设、换模型、设置里的“模型”，都用同一个选择器。

- 收起时是一个字段：左边一格供应商名，中间是模型名和 `<供应商>/<模型 ID>`，右边是窗口、能不能收图、支持的思考级别。点它展开。
- 展开后是一块面板：顶上是搜索框，下面是最近用过的几个，再下面按供应商分组。
- 搜索按空格分词，每个词都要在供应商名或模型名里出现。回车选第一个。
- 配好 key 的供应商排在前面。每组的组头吸在顶上，右边写 key 状态：已配、OAuth（tau 不支持）、没配、tau 读不了。
- 没配 key 的组变暗，里面的模型照样能选。
- 选了没配 key 的模型，字段下面写一行提示：这家还没配 key，进程第一次调模型时会出错；key 在 pi 的 `auth.json` 里配。OAuth 和读不了的各有各的提示。
- 每个模型一行：名字、窗口（128K、1M）、能收图的标 IMG、六个小格。六格固定是 minimal、low、medium、high、xhigh、max，亮的是这个模型支持的。
- 选中的行反成浅色，左边一条黄。
- 最近用过的记进界面数据。建预设、改预设、换模型、设默认时记。
- 预设里写的模型不在目录里（手写的）：字段照样显示原值，标“目录里没有”，不改它。
- 模型目录读不到：退回一个文本框，手写 `<供应商>/<模型 ID>`。

思考强度紧跟在模型后面：

- 一排分段按钮：“不思考”加这个模型支持的几档。选中的是黄块。
- “不思考”就是预设里不写 `thinking`。目录里的 `off` 不单列。
- 换了模型，原来的级别不被支持，就换成支持的最近一档，距离一样取低的，并在按钮下写一行：换成了哪一档。这个模型没有可选的级别，就改成不思考。
- 目录里没有这个模型时，不知道它支持什么，六档都给，也不动已选的。

### 7.9 改预设

- 入口：常驻团队行的右键菜单，没有进程的预设行的右键菜单，详情栏概况页里的“改预设”。
- 弹窗和[新预设](#76-新预设)共用一张表：
  - 预设 ID，只读。工作目录也不能改。
  - 模型和思考强度，见[7.8](#78-模型和思考强度)。
  - 记忆和工具。内置工具是 read、write、edit、bash、memory、agents；另一组是已装的工具定义（[7.12](#712-工具定义)）。文件里写了、但没装的工具名原样保留，可以取消。
  - 换段阈值，可以不填。
  - “拼上项目的 AGENTS.md”，规则同[7.6](#76-新预设)。勾选的初值是预设里现在有没有这一段；文件没了又勾着时只能取消。取消勾选，保存时去掉这一段。
  - 提示词。只编辑用户自己写的部分，拼进来的那一段不在框里，保存时界面按勾选原样接回。
  - AGENTS.md 改过了（块和文件不一致）时，勾选旁写“改过了”，多一个“保存时重新拼”；不点，保存别的东西不会动那一段。
  - 折起的“高级”：`options`，一行 JSON。
- 底部一条检查结果：现在的文件能启动，或者用警示色写出错误原文。
- 保存只发变了的字段。去掉的字段发 `null`。没有改动时保存键不可用。
- 保存以后服务马上 `check`。读不出或者起不来，服务把旧文件改回去，错误原文写在检查条里，弹窗不关。
- 一行说明：改了只对新开的进程生效；在跑的进程要换模型，用“换模型”。
- 现在读不出的预设没法改：界面不知道它的各个字段。弹窗里写出错误原文，请用户去编辑器里改。

### 7.10 换模型

- 入口：进程铭牌上，在“分叉”旁边。小窗贴着按钮。进程在跑时不可用，和“分叉”一样。
- 顶上写这个进程冻结的模型和思考强度。
- 两种换法，默认第一种：
  - 改这个预设的模型。用[7.8](#78-模型和思考强度)的选择器选模型和思考强度。确认时先改这个进程的预设（和[7.9](#79-改预设)同一条路，`check` 通过才算），再 `fork` 带 `preset`（同一个预设 ID）。预设 ID 不变，所以记忆库还是同一个，以后新开的进程也用新模型。选的和进程冻结的一样时，确认键不可用。
  - 换同一个项目里的另一个预设。直接 `fork` 带它。新进程用那个预设的提示词和工具，记忆库跟着它走。
- 窗里写清代价：
  - 带着当前这一段的上下文开一个新进程，进程 ID 会变。
  - 旧进程留着。它的回信和它开的子进程，都留在旧进程那里。
  - 第一种换法里，预设也一起改了。
- 预设改成功、分叉失败时，窗里写明预设已经改了。
- 分叉成功后聚焦新进程，进程栏照旧写“分叉自 <ID>”。

### 7.11 设置

- 入口：项目窄条底座，总管按钮的旁边；快捷键 Ctrl+,。
- 改一项记一项，没有“保存”。
- 默认模型和默认思考强度：新建预设时预填。选择器和[7.8](#78-模型和思考强度)一样。可以清掉。
- 供应商和 key：只读列表，配好的在前。每家写模型个数和 key 状态：已配、OAuth（tau 不支持）、没配、tau 读不了。界面不显示 key。
  - 一行说明：key 在 pi 的 `~/.pi/agent/auth.json` 里改，改完不用重启。
  - 界面不改 key。这个文件读不出时，写出原因，不带文件内容。
- 清理旧进程的天数。和[清理弹窗](#75-清理旧进程)里是同一个值。
- 完成通知：开或关，默认关。打开时当场向浏览器申请通知许可；被拒绝或浏览器不支持，开关旁写原因，开关不打开。规则见[第 9 节](#通知标题和图标)。
- 标题用的模型：选择器和[7.8](#78-模型和思考强度)一样，没单独设就跟默认模型一样，默认模型也没设就用进程自己的模型。可以清掉。用途见[自动标题](#自动标题)。
- 工具定义：一行，按钮打开[工具定义](#712-工具定义)。
- 不放 token 和费用。

### 7.12 工具定义

- 入口：设置里的“工具定义”一行；地址栏 hash 是 `#dlg=tools`。
- 上半是 `~/.tau/tools/` 里已装的定义：名字、说明、参数名、超时、输出方式、命令，用到它的预设。读不出的写原因。
- 下半是工具库（仓库的 `extras/tools/`，做什么见 [kb-extras 的工具库](../../.knowledge/kb-extras.md#工具库)）：每个写说明、参数、状态：未安装、已安装、和库里不同。
- 安装：写 `~/.tau/tools/<名字>.json`，先写临时文件再改名。同名文件已有、内容和库里不同，不覆盖。
- 更新：状态是“和库里不同”时才有。行里先确认，再覆盖。
- 删除：行里先确认，删了找不回。有预设在用就不让删，写明是哪些预设。
- 工具定义文件不许多余字段，所以“是不是库装的”只靠比较内容：和库里逐项一样才算已安装。
- 预设表的工具区分两组：内置的六个，已装的工具定义。预设里写了、但 `tools/` 下没有的，原样留着，标出来。`shell` 和 `bash` 同时勾上时，写一行提示。
- 只对新开的进程生效。

MCP（弹窗的第三节，编号 03）：

- 先选项目，默认是现在聚焦的那个，可以从已知项目里换。项目的 MCP 配置在 `.pi/mcp.json`，没有就 `.mcp.json`。一个项目都没有时写“先打开一个项目”。
- 每个服务器一张卡：名字、命令（等宽）、说明、超时。配置写错的那一项写错误原文，不给“列出工具”的按钮。
- 卡上“列出工具”。要起服务器，可能要好几秒，按钮上写“正在列”。出错写原文。
- 工具清单一行一个：勾选框、定义名、和原名不同时补写原名、状态（未装、已装、和现在的不同）、字节数。装不了的不能勾，写原因。默认勾上没被跳过的全部。
- 大小条：勾选的字节数对着一个预设的上限 64 KiB。超了变警告色，写“一个预设用不下这么多，少勾几个”。只是提示，不拦安装：不同预设可以各用一部分。
- “装选中的”写进 `~/.tau/tools/`。同名的文件已经存在、又不是 MCP 生成的，一个都不写，列出冲突的名字。
- 服务器上已经没有的定义单独列出来，每个一个“删除”。被预设用到的不让删，写是哪些预设。
- 服务器的说明有内容时折起来放在清单上面，点开看全文，带“复制”，写一句：工具描述里不带它，要模型知道就贴进预设的提示词。
- 底部一行中转的状态。没在跑写“中转没在跑，第一次调用时自动起来”；在跑写几个实例、每个的进程、服务器、空闲多久、在跑的调用数。打开弹窗和每次操作后读一次，不轮询，旁边“刷新”。
- 预设表的工具定义里，MCP 生成的按服务器分小组。小组头写服务器名，带“全选”“全不选”。

### 7.13 记忆

- 入口：项目概况里带记忆的预设行的“记忆”，和进程概况里进程的预设带记忆时的“记忆”。地址栏 `#dlg=memory&ns=<预设 ID>`。
- 标题是预设 ID 加“记忆”。列出这个库的全部键，按键的字节序，和服务给的一样。每个键写值和版本号。多行或超过 80 字的值先折成第一行，点“看全文”展开。
- 值只能是字符串。用文本框改，不是 JSON。
- 能改值、加新键、删键。写用 `memory_write`，带读到的版本号。新键带 `null`。键和值的字节上限由服务查，页面只转述哪一项超了、多少字节。
- 删键先在那一行确认，写明删了找不回。
- 版本冲突（兄弟进程刚写过）时不覆盖：重读，写“别处刚改过，已重读”。用户写的字原样留在文本框里，下面列出别处现在的值给他对照，保存键改成“仍然保存”。别处把键删了就写明，保存会重建它。删的时候冲突，重读后不删，写明。
- 回到这个页面时重读。正在编辑的字不动，冲突留到保存时发现。
- 一行说明：写入马上进库；运行中的进程用 `memory_get` 读到的是最新的，提示词里挂的那份是开段时的快照，换段或新开进程才更新（[kb-memory](../../.knowledge/kb-memory.md#谁有记忆库)）。这和预设不同：预设改了只对新进程生效，记忆写了对在跑的进程也生效，只是要它自己去读。
- 预设没有 `memory` 工具时，写一句进程自己读写不了这个库。没有键的库显示空状态和“加一条”。

### 7.14 改动

- 入口：详情栏“改动”页里点一个文件。没有地址栏参数，因为它要带工作目录和文件。
- 标题是文件名，副标题依次是目录、状态标记、增删行数。状态里没有数字时不写增删。
- 只显示 git 的原样输出，界面不算 diff。旧、新两列行号从 hunk 头读。文件头的 `diff --git`、`index`、`---`、`+++` 不显示。
- 窗开着时每 10 秒刷新一次状态和 diff。
- 底部“上一个”“下一个”和 Alt+↑、Alt+↓ 按文件树的顺序换文件。当前文件不在状态里（例如刚提交）时，计数写“—”，两个键都灰掉。
- 底部还写这个 diff 用的 git 命令。

## 8. 视觉

方法学自《明日方舟：终末地》，不照搬素材。

- 印刷的比喻：墨黑加一种专色黄。黄色只做整块的面，上面压黑字。一屏最多一大块黄，其余是小记号。
- 字号差到八倍以上：压窄的大数字、拉宽的全大写英文标签、很重的中文标题。拉宽的全大写英文标签只用于英文代号，中文小标保持紧凑字距；动态数字等宽对齐。
- 装饰必须是真数据：三相灯是内核的三个阶段，段尺是上下文用量，底纹大字是第几段。
- 暗边亮台：窄条、进程栏、详情栏、写信条是暗的，中间台面是打了灯的灰。不用大面积纯白。
- 每个面带淡材质：台面上是网格和等高线，黄色铭牌上是网点，暗栏上是网点、网格和斜线。浓度在 4% 到 15% 之间，用遮罩渐隐。
- 直角。动作按钮带右下 45° 切角、文字与图标分仓槽和底边厚度，分标准和紧凑两档。拨档、状态筛选器和窄条键组共用右下 45° 切角的联排机械底座。窗口关闭、消息分叉、代码复制用带底边的直角键帽。
- 不用透视，也不用 3D。
- 详情栏的版面（2026-11-17 打磨）：
  - 小节标题前有一个 7px 的黄方块，后面是英文标签、一条线、右边的计数。
  - 每页顶上三格数字：英文小标签在上，压窄的大数字，中文说明在下。有待办（信箱里排着信）的格子，数字压在黄块上。数字按格宽定字号：短的一样大，长的缩小，永远不出格。改动的“增 / 删”两个数上下两行，各占半高，合起来和旁边的大字一样高。
  - 一个事实占一块，不平铺成表单：上下文是一块暗色小铭牌，信箱里每封信是一张卡。卡是暗灰底，左边一条竖线：灰是普通，黄是进行中或已装，橙是出错或和库里不同。
  - 刻线和标签不压字：标签放在尺的下面，贴着刻线的竖杆。刻线在右半边时，标签靠右对齐，不出界。
- 弹窗里的列表（工具定义、记忆、设置的供应商）同一套：一行一张卡，状态用 tag，动作在右边或卡的底行。一节和上一节之间多留一格。
- 旧代码横幅的层级低于弹窗，弹窗开着时在它下面，不盖住弹窗的按钮；详情栏的页底留出它的高度。

| 用途 | 取值 |
|---|---|
| 暗面，从深到浅 | `#0B0C0B`、`#131413`、`#191A18`、`#242622`、`#32342F` |
| 暗面上的字 | `#ECEDE9`；次要 `#A5A7A0`；更弱 `#72746E` |
| 台面 | 径向渐变 `#EAEBE6` → `#DFE0DA` → `#D2D4CE` |

| 墨黑 | `#111211` |

## 9. 交互和动效

- 动效只用来说明状态变了，不为好看而动。
- 悬停提亮一格，按下再深一格。键盘焦点是信号色的四角括号。选中用反色，再加一条黄边。
- 时长分三档：快 120ms（悬停、按下），中 200ms（选中移动、换选项卡、新消息），慢 320ms（弹窗、出错擦色）。离场用 160ms，比进场快。
- 进场曲线 `cubic-bezier(.2, 0, 0, 1)`，离场曲线 `cubic-bezier(.4, 0, 1, 1)`。
- 阶段灯直接跳，不渐变。只有真在跑的东西才有脉冲。流式光标只在模型正在写的时候出现。
- 出错只变色，不闪烁，不抖动。
- 消息流跟着末尾走的时候，留白进纸，不一行一行地挪（2026-11-17 用户定的：“滚动次数应该减少，每次都留出余量”）：
  - 末尾离台面底边不到一行半时，整段平滑地推上去，让末尾停在台面六成高的地方，下面留四成空白。
  - 字在空白里写，页面不动；写满了再进一次。读字的时候页面要静止，眼睛不用追着跑。
  - 推的动作是临界阻尼的弹簧，起步和停下都是缓的，约 0.4 秒停稳。
  - 消息流底部常备这四成空白，收尾时内容变矮，页面也不会跳。
  - 要推的距离超过一屏（切进程、展开折起的消息），直接到位，不滑。
- 用户往上翻着读的时候，新消息只在底下提示，不把视图拽到底。只有用户自己的操作（滚轮、触摸、键盘、拖滚动条）能让视图离开末尾；翻回到看得见末尾，就重新跟着走。
- 系统开了“减少动画”，就全部瞬间切换。

### 通知、标题和图标

要看的东西有两类，页面内存里算，不进界面数据：

- 待你看：`derive.js` 的 `attention`，出错的进程（[总管](#71-总管)和窄条上的角标用的是同一个）。
- 新结果：根进程（没有父进程，人建的）一轮结束，不管什么原因。子进程正常结束不算，它们的结果寄给上一层。用户聚焦到那个进程就清掉；页面不在前台时不清，人不在看。页面刚打开时已经结束的轮不算。

- 标签页标题：两类合起来、去重后有 N 个进程时是 “(N) tau”，没有就是 “tau”。不管通知开没开。
- 图标：画在 canvas 上的 tau，N 大于 0 时右上角加一块信号黄。不管通知开没开。
- 通知：设置里开着，浏览器许可了，并且一个进程刚进入“待你看”或刚有了新结果、页面又不在前台（标签页被隐藏或窗口没焦点）。页面在前台、聚焦的不是它时，只计数，不弹。
  - 标题是进程的显示名，正文是结束原因加最终回复的第一行（截短）。
  - 同一个进程同一轮只通知一次：两类同时成立（根进程出错）也只弹一条；离开“待你看”再进入，才算新的一轮。
  - 页面刚打开时已经在“待你看”或已经结束的，不通知。
  - 点通知：聚焦窗口，跳到那个进程。

### 旧代码横幅

服务和桥都是常驻的，改了代码要重启才生效。页面不让人猜：

- 判断：服务（或桥）的启动时间早于它用到的源码的最新修改时间，就是在跑旧代码。服务看 `src/` 和依赖清单，桥看 `extras/gui/bridge/` 和 `extras/tools/`。
- 显示：一条横幅，不挡操作。宽屏时浮在详情栏底部，让开右边的页签栏；详情栏挪到下面以后（窄于 1180），改成贴底的一整条。写“服务在跑旧代码”或“桥在跑旧代码”，后面跟“重启服务”或“重启桥”按钮。
- 重启服务会中断在跑的进程。有进程在跑时，横幅先变成确认：写明会中断 N 个进程，在跑的工具调用会报“被中断”，不自动重做。确认了才重启。
- 重启桥不动进程。页面靠自己的重连回来。
- 点了以后横幅写“正在重启…”，新的状态读到、不再是旧代码就消失；等了 45 秒还没好也消失。
- 和服务断开时，断开提示里多一个“拉起服务”按钮。服务没在跑时，它就是启动服务。
- 桥自己没在运行时，这些都做不了。要用 `extras/gui/start.ps1` 或 `restart.ps1`。

### 自动标题

- 只给人建的根进程起（没有 `parent`）。子进程照旧用第一封信的第一行。
- 第一封信到了、这个进程没起过，页面就让桥调一次模型，把第一封信概括成不超过 16 个字的标题。同一个进程只试一次。失败就算了，照旧显示第一行，不重试。
- 生成的标题和第一行标题放在一起（`titles`），并记进 `titled`，以后不再起。
- 模型见[设置](#711-设置)的“标题用的模型”。代价是多一次模型调用；桥没在运行时不起标题。

## 10. 数据从哪来

请求的细节见 [kb-service 的线协议](../../.knowledge/kb-service.md#线协议srcprotocolts)和[历史和订阅](../../.knowledge/kb-service.md#历史和订阅)。

| 界面上的东西 | 从哪来 |
|---|---|
| 进程、阶段、步数、排队的条数、模型、上下文、段号、本段消息数、父进程 | 先用 `ps` 取全部，再用 `watch` 收每个进程的 `update` |
| 团队行的角标、谁开的 | 每个进程的 `parent`。`update` 只带 `self`，所以子进程的个数由界面按 `parent` 自己数 |
| 流式文本 | `watch` 推的 `text`。不带 `kind` 的是正文，`thinking` 是思考，`toolCall` 是工具调用参数的片段 |
| 消息流、最终回复、在做什么 | `watch` 带 `messages: true`，每步追加的消息直接并进缓存（`message` 带 `process`、`segment`、`seq`）。`history` 只用来补：第一次打开进程、重连、换段、分叉，以及推来的消息接不上（漏了几条）时。总是带上 `segment`。信的来历读消息的 `tau`。界面同时记着段号和条数：缓存比 `self.messages` 少，就用 `from` 读缺的；段号变了，先把旧段剩下的读完，再从 0 读新段 |
| 重连时漏掉的消息 | 重连从 `ps` 重来：缓存比 `self.messages` 少的，用 `history` 的 `from` 补。`seq` 说了算：已有的丢掉，跳号的不收，推送和补读重叠也不重复、不丢 |
| 在当前阶段待了多久 | 当前段最后一条消息的时间戳：等模型时从它算起，等工具时从带调用的那条助手消息算起 |
| 结束原因、出错 | 空闲阶段的 `ended`，已截短 |
| 项目、常驻还是临时、工具 | `inspect` 读进程记录里冻结的预设快照：`workdir`、`tools` 加工具定义的名字。预设文件之后改了也不影响。没读到快照的进程不归进任何项目 |
| 预设能不能用 | `check`：读得出、能不能启动，错误文字和 `start` 一致。桥只列出文件名，不自己解析预设 |
| 信的发送者、回信的结束原因、换段后的第一条、被中断的工具结果 | 段里消息的 `tau`，不解析文字 |
| 临时进程的标题 | 读第 1 段，取第一封信正文的第一行，缓存在 `~/.tau/extras/gui/`。`prune` 或 `remove` 之前先缓存 |
| 最后动静的时间 | 当前段最后一条消息的时间戳 |
| 改动、分支、提交 | 在工作目录里跑 git，带 `--no-optional-locks` |
| 后台命令 | `~/.tau/extras/bg/<进程 ID>-<名字>.log`。有退出码那一行就是结束了；没有时只写“没看到退出码”：机器重启或子 shell 被杀时，那一行永远不会来 |
| 寄信、建进程、分叉、停止、删除 | `send`、`start`、`fork`、`stop`、`remove`、`sweep` |
| 记忆库的键、值、版本号；改、加、删 | `memory`、`memory_write` |
| 新建、改、删除预设 | HTTP 桥写、改或删 `~/.tau/presets/<ID>.md`。改完立刻 `check`，不行就改回去 |
| 模型目录、窗口、能不能收图、思考级别 | HTTP 桥读 pi-ai 的目录，进程启动时算一次 |
| 供应商的 key 状态 | HTTP 桥读 pi 的 `~/.pi/agent/auth.json`，只看每条的供应商名和类型，不回 key |
| 进程冻结的模型、思考强度、换段阈值、`options` | `inspect` 的快照 |
| 段尺上的“自动换段”刻线 | `inspect` 的 `limits.threshold` 比 `process.preset.contextWindow` |
| 排队的信，谁在等谁 | `inspect` 的 `process.phase.turn.queued` 和 `turn.replyTo` |
| 模型收不收图片 | `inspect` 的 `process.preset.input`；还没有进程的总管用模型目录 |
| 显示名、总管、当前进程、钉住、顺序、简称、折叠、清理的天数、最近用过的模型、默认模型和思考强度、完成通知开关 | `~/.tau/extras/gui/` |

## 11. 不显示的

界面不显示下面这些，也不靠读段去猜。

[D64](../../.knowledge/kb-decisions.md#d64-内核的自由度给上层事实对称的控制和可组合的动作) 以后内核能给的，已经接的是：排队的信、谁在等谁、离换段的阈值有多远（见[第 6 节](#6-详情栏)）。还没接的：

- **信的跳数。** D64 以后用 `inspect` 和段里消息的 `tau`。
- **排队的信的时间。** 信件本身不记时间，`inspect` 里没有，不编。
- **撤回排队的信。** D64 判为不做。

这一样内核给不了：

- **按进程分的改动。** git 的状态属于工作目录，不属于进程。改动页写的是工作目录的改动。
